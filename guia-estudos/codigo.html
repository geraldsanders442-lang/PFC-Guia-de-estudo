Código por funcionalidade

O caminho real de cada ação, do clique ao resultado na tela, com os arquivos e as linhas.

Como estudar: para cada funcionalidade, decore o quadro (quem inicia, o que entra, onde grava, o que volta), depois abra o trecho e explique linha por linha em voz alta. Os links dos trechos abrem o GitHub na linha exata.

Mapa do projeto

Quatro lugares onde o código roda.

Onde rodaArquivosResponsabilidade
Navegador (tela)*.html, js/main.js, js/paginas/, js/componentes/capturar eventos e desenhar o DOM
Navegador (regras e rede)js/servicos/, js/modelos/, js/nucleo/chamar a API, manter o estado, gerar a sala
Web Workerjs/nucleo/PyodideWorker.jsexecutar o Python do jogador

Não existe camada "repository": os arquivos de backend/src/services/ contêm as regras e as chamadas ao driver do MongoDB. Também não há classes de model no back-end; o formato dos documentos é definido no código que os grava.

Login, sessão e 2FA

Primeiro fator, segundo fator e o JWT.

backend/src/services/autenticacao.js · linhas 91–114
91export async function entrar(ctx, corpo) {
92  const email = normalizarEmail(corpo.email);
93  const senha = typeof corpo.password === "string" ? corpo.password : "";
94  if (!senha || senha.length > 200) throw credenciaisInvalidas();
95
96  const usuario = await buscarPorEmail(ctx, email);
97  if (usuario?.legacy?.pendingTwoFactor) {
98    exigirLegado(ctx);
99    return entrarPeloLegado(ctx, email, senha, usuario);
100  }
101  if (!usuario) {
102    if (ctx.legado) return entrarPeloLegado(ctx, email, senha, null);
103    await bcrypt.compare(senha, HASH_FICTICIO);
104    throw credenciaisInvalidas();
105  }
106
107  const confere = await bcrypt.compare(senha, usuario.passwordHash || HASH_FICTICIO);
108  if (!confere || !usuario.passwordHash) {
109    // Alguém pode ter cadastrado o e-mail de uma conta antiga sem confirmá-lo; o dono comprova pela conta antiga
110    if (ctx.legado && !usuario.emailVerified && !usuario.firebaseUid) return entrarPeloLegado(ctx, email, senha, usuario);
111    throw credenciaisInvalidas();
112  }
113  return concluirPrimeiroFator(ctx, usuario, "E-mail e senha");
114}
  • Conta inexistente e senha errada devolvem a mesma mensagem CREDENCIAIS_INVALIDAS.
  • Quando o e-mail não existe, o servidor ainda roda bcrypt.compare contra um hash fictício, para o tempo de resposta não denunciar quem tem cadastro (com a migração do Firebase ligada, esse caso consulta o Firebase em vez disso).
  • Com 2FA ativo, o primeiro fator não entrega sessão: entrega um "desafio" de 5 minutos.

O segundo fator (TOTP)

O app autenticador e o servidor compartilham um segredo. O código de 6 dígitos deriva do segredo e do relógio, em períodos de 30 s. O segredo fica cifrado com AES-256-GCM e o "passo" usado é gravado para o mesmo código não valer duas vezes.

backend/src/services/doisFatores.js · linhas 77–96
77export async function conferirSegundoFator(ctx, usuario, { code, recoveryCode }) {
78  const usuarios = ctx.db.collection("users");
79  if (recoveryCode) {
80    const hash = hashRecuperacao(recoveryCode);
81    const r = await usuarios.updateOne(
82      { _id: usuario._id, "twoFactor.recoveryCodes": hash },
83      { $pull: { "twoFactor.recoveryCodes": hash } }
84    );
85    return r.modifiedCount === 1;
86  }
87  if (!usuario.twoFactor?.secret || !/^\d{6}$/.test(code || "")) return false;
88  const passo = passoValido(decifrar(usuario.twoFactor.secret, ctx.config.chaveTotp), code);
89  if (passo === null) return false;
90  // Impede que o mesmo código seja reaproveitado dentro da janela de validade
91  const r = await usuarios.updateOne(
92    { _id: usuario._id, "twoFactor.lastUsedStep": { $lt: passo } },
93    { $set: { "twoFactor.lastUsedStep": passo } }
94  );
95  return r.modifiedCount === 1;
96}

Como o JavaScript fala com a API

Um único fetch para todas as chamadas REST.

js/nucleo/Api.js · linhas 37–60
37static async requisitar(metodo, caminho, corpo) {
38  const cabecalhos = {};
39  if (corpo !== undefined) cabecalhos["Content-Type"] = "application/json";
40  if (Api.token) cabecalhos.Authorization = `Bearer ${Api.token}`;
41
42  let resposta;
43  try {
44    resposta = await fetch(Api.url(caminho), {
45      method: metodo,
46      headers: cabecalhos,
47      body: corpo !== undefined ? JSON.stringify(corpo) : undefined
48    });
49  } catch {
50    throw new ErroApi(0, "SEM_CONEXAO", "Sem conexão com o servidor. Verifique sua internet e tente novamente.");
51  }
52
53  if (resposta.status === 204) return null;
54  const dados = await resposta.json().catch(() => null);
55  if (resposta.ok) return dados;
56
57  const erro = dados?.erro || {};
58  if (resposta.status === 401 && erro.codigo === "TOKEN_INVALIDO") Api.esquecerToken();
59  throw new ErroApi(resposta.status, erro.codigo || "ERRO", erro.mensagem || "Não foi possível concluir a operação.");
60}

Leitura linha a linha:

  • async faz a função devolver uma Promise; await fetch(...) suspende só esta função até a resposta chegar, sem travar a tela.
  • JSON.stringify transforma o objeto em texto para viajar; resposta.json() faz o caminho inverso.
  • fetch só rejeita em falha de rede (cai no catch e vira SEM_CONEXAO). Um 404 ou 500 resolve normalmente, por isso o teste de resposta.ok.
  • 204 significa sucesso sem corpo.
  • Em 401 TOKEN_INVALIDO o token local é apagado.

O endereço da API muda sozinho conforme o domínio:

Convite por username

O _id do convite é idDoGrupo_idDoConvidado, então não existem dois convites pendentes iguais. Aceitar primeiro "reserva" o convite (status: "pending" → accepted) e depois tenta ocupar a vaga; se o grupo encheu, o status volta para pendente.

81export async function responderConvite(ctx, usuario, id, corpo) {

107}

16export function calcularPontuacao({ dificuldade, resolvidos, dicas, tentativas, restanteMs }) {
17  const bonus = Math.floor((Math.max(0, restanteMs) / 1000) * BONUS_POR_SEGUNDO[dificuldade]);
18  const total = resolvidos * BASE_POR_ENIGMA + bonus - dicas * PENALIDADE_DICA - tentativas * PENALIDADE_TENTATIVA;
19  return Math.min(PONTUACAO_MAXIMA, Math.max(0, total));

Fórmula: 200 × enigmas + piso(segundos restantes × bônus) − 40 × dicas − 10 × tentativas, limitada entre 0 e 5000. Bônus por segundo: fácil 0,15; médio 0,10; difícil 0,08. O front calcula a mesma fórmula, mas o campo score enviado é ignorado. Os números são decisão de projeto: não há no repositório estudo que os fundamente, então apresentem como escolha da equipe.
