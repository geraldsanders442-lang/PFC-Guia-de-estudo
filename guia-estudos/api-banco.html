API e cliente-servidor

O contrato entre o navegador e o servidor.

Uma API é o conjunto de operações que um programa oferece a outro. A nossa é própria (Node.js + Express) porque as regras precisam rodar em um lugar que o jogador não controla e porque a senha do banco não pode ir para o navegador.

Middlewares

Funções em fila entre a requisição e a resposta.

Um middleware recebe (req, res, next). Ele pode preparar dados, responder e encerrar, ou chamar next(). Existe para não repetir a mesma verificação em cada rota. O controller é o fim da fila: lê o que precisa de req, chama o service e monta a resposta.

5export async function autenticar(req, res, next) {
6  const [esquema, token] = (req.get("authorization") || "").split(" ");
7  if (esquema !== "Bearer" || !token) throw naoAutenticado("Faça login para continuar.", "TOKEN_AUSENTE");
8
9  let dados;
10  try {
11    dados = lerSessao(req.ctx, token);
12  } catch {
13    throw naoAutenticado("Sua sessão expirou. Entre novamente.", "TOKEN_INVALIDO");
14  }
15
16  // Redefinir a senha incrementa sessionVersion e derruba as sessões anteriores
17  const usuario = await buscarPorId(req.ctx, dados.sub);
18  if (!usuario || (usuario.sessionVersion || 0) !== dados.ver) {
19    throw naoAutenticado("Sua sessão expirou. Entre novamente.", "TOKEN_INVALIDO");
20  }
21  req.usuario = usuario;
22  req.sessaoEmitidaEm = dados.iat * 1000;
23  next();
24}

backend/src/middleware/erros.js · linhas 8–26
8export function tratarErros(erro, req, res, next) {
9  if (res.headersSent) return next(erro);
10
11  if (erro instanceof ErroHttp) {
12    return res.status(erro.status).json({ erro: { codigo: erro.codigo, mensagem: erro.message, ...erro.extras } });
13  }
14  if (erro.type === "entity.parse.failed") {
15    return res.status(400).json({ erro: { codigo: "JSON_INVALIDO", mensagem: "O corpo da requisição não é um JSON válido." } });
16  }
17  if (erro.type === "entity.too.large") {
18    return res.status(413).json({ erro: { codigo: "CORPO_GRANDE", mensagem: "Os dados enviados são grandes demais." } });
19  }
20  if (erro.message === "ORIGEM_NAO_PERMITIDA") {
21    return res.status(403).json({ erro: { codigo: "ORIGEM_NAO_PERMITIDA", mensagem: "Origem não autorizada." } });
22  }
23
24  console.error("[erro]", req.method, req.originalUrl, erro);
25  res.status(500).json({ erro: { codigo: "ERRO_INTERNO", mensagem: "Erro interno. Tente novamente em instantes." } });
26}
Os handlers são async e não têm try/catch: no Express 5, uma Promise rejeitada é encaminhada sozinha ao middleware de erro.

6function resumir(partida, status) {
7  const { dicas, tentativas } = somarUso(partida.solved);

27function statusEncerrado(partida) {
28  if (ENCERRADAS.includes(partida.status)) return partida.status;
29  if (partida.status === "PLAYING" && partida.expiresAt <= new Date()) return "EXPIRED";
30  return null;
31}

33// Idempotente: a chave (groupId, createdAt) identifica a partida e impede registros duplicados
34export async function arquivarPartida(ctx, partida) {
35  const status = partida && statusEncerrado(partida);
36  if (!status) return;
37  const resumo = resumir(partida, status);
38  await ctx.db.collection("gameHistory").updateOne(
39    { groupId: resumo.groupId, createdAt: resumo.createdAt },
40    { $setOnInsert: { _id: new ObjectId(), ...resumo } },
41    { upsert: true }
42  );
43}
44
45export async function arquivarPartidaDoGrupo(ctx, gid) {
46  await arquivarPartida(ctx, await ctx.db.collection("games").findOne({ _id: gid }));
47}

Os três momentos do arquivamento

  1. Conclusão (registrarEnigma do enigma final).
  2. Desistência ou tempo esgotado (encerrarPartida).
  3. Exclusão do grupo (apagarGrupo), antes de remover o documento: cobre a partida vencida que ninguém encerrou.

O índice único (groupId, createdAt) torna a operação idempotente: arquivar duas vezes não duplica. Partida ainda em andamento, dentro do prazo, não vira histórico quando o grupo é excluído. Partida cancelada no lobby também não.

A atualização em games e a gravação em gameHistory são duas operações separadas, sem transação. Se o processo caísse entre elas, a partida ficaria concluída sem resumo; excluir o grupo arquivaria, mas iniciar uma nova partida apagaria o documento sem arquivar.

Isolamento entre grupos e jogadores é feito no servidor: o uid sai do token e cada operação de grupo passa por grupoComoMembro ou grupoComoDono; histórico e estatísticas filtram por players: uid. Todos compartilham o mesmo banco e as mesmas coleções.

Regras aplicadas antes de gravar

  • Formato e tipo (utils/validacao.js).
  • Permissão (dono, membro, jogador, admin).
  • Estado (transição de status, prazo, dependências) no filtro da própria escrita.
  • Unicidade pelos índices.

O banco não tem validação de schema ($jsonSchema): quem garante o formato é a aplicação.
